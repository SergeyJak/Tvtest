# Эксперимент: три CDN для VF Теория большого взрыва

## Подготовка

В админке https://tv.heysmart.lv/admin/ должны быть настроены три
независимых кабинета Edem (основной, резерв 2, резерв 3). Назначьте
**разные CDN-регионы в настройках самих подписок Edem**. Никакие ключи,
M3U URL и настройки CDN не фиксируются в Git.

В каждом исходном M3U должно присутствовать название канала
`VF Теория большого взрыва` (регистр и лишние пробелы неважны).
Если другого кабинета или канала нет, основной кабинет продолжает
работать через прежний Gateway. Для остальных каналов ничего не меняется.

## Как работает пилот

- В момент просмотра именно этого канала в **первом** кабинете шлюз
  прогревает три отдельных исходных потока через существующие managers.
  Из трёх независимых подписок выбирается текущий источник.
- Главный кабинет — предпочтительный стартовый источник. Если он
  перестаёт получать свежие сегменты, шлюз может выбрать запасной
  (прошло не менее 18 секунд с последнего переключения, резервный поток
  готов и у него поступают новые сегменты).
- Телевизор не получает токенов и адресов резервных подписок.
  Внешний M3U URL, ID канала и пути TV остаются прежними.
- Сегменты **не перемешиваются между разными CDN**. При переключении
  формируется виртуальная монотонная последовательность HLS, а переход
  между потоками маркируется `#EXT-X-DISCONTINUITY`. В результате
  может быть небольшой скачок вперёд по эфиру или переподключение
  декодера. Отсутствует гарантия безразрывного переключения
  на каждой модели ТВ.
- Хранится ограниченное число сегментов для старых запросов телевизора,
  с ограничением на дополнительную память. Старые потоки через EPG
  и кабинеты 2/3 продолжают работать отдельно.
- Админка → Обзор показывает выбранный кабинет, готовность резервов,
  возраст последнего сегмента, размер буфера и счётчик переключений.
  Статистика доступна только после входа в админку.

Если один из резервных кабинетов занят просмотром **другого** канала
и достиг своего лимита, эксперимент не прерывает его просмотр.
Даже если резерв ещё не настроен или временно занят, **первый
кабинет с самого начала получает виртуальные HLS номера сегментов**.
Появление резерва позднее не меняет URL и нумерацию уже выданного видео.
Фоновые проверки CDN не продлевают сессию реального зрителя в другом
кабинете и не блокируют переключение его каналов.

При остановке продвижения выдаваемого ТВ-плейлиста дольше 18 секунд
шлюз переключается на готовый CDN, даже если старый продолжает
скачивать сегменты. После 45 секунд без запросов плейлиста начинается
новая сессия без воспроизведения старого окна (сохраняется монотонность
виртуальных номеров).

## Применение

1. После слияния PR обновите код: `cd ~/Tvtest && git pull --ff-only`.
2. Назначьте три разных CDN-региона в настройках Edem.
3. Обновите M3U-снимки, чтобы получить новые региональные адреса,
   без скачивания большого XMLTV:

```bash
cd ~/Tvtest
python3 iptv_profile_jobs.py --refresh-m3u --m3u-only
```

При изменении состава каналов опция `--m3u-only` **не удаляет
последнюю работающую EPG**: старый файл остаётся до успешного
атомарного обновления новым XMLTV.

Каждый настроенный кабинет должен вернуть `refreshed_m3u`. Если
кабинет вернул `failed`, проверьте его источник до переключения.

4. Перезапустите шлюз и административную панель:

```bash
sudo systemctl restart iptv-gateway.service iptv-admin.service
sudo systemctl is-active iptv-gateway.service iptv-admin.service
```

Это перезапустит текущие трансляции на несколько секунд.
Перезагружать Caddy и менять телевизионные ссылки не нужно.

**Быстрый откат эксперимента**, если клиент плохо переносит переходы
между потоками, не требует отката PR:

```bash
cd ~/Tvtest
touch .iptv_profiles/multicdn.disabled
sudo systemctl restart iptv-gateway.service
```

Чтобы снова включить:

```bash
cd ~/Tvtest
rm -f .iptv_profiles/multicdn.disabled
sudo systemctl restart iptv-gateway.service
```

Файл-маркер расположен в закрытой директории настроек и не содержит
секретов. При переключении режима активный плеер может потребовать
повторно выбрать канал.

## Ограничения

- Один плеер пока тестируется на канале VF. Это не система объединения
  пропускной способности: три параллельных скачивания не ускоряют
  отдельный сегмент одного CDN.
- Все три подписки зависят от поставщика Edem. Если сбой происходит
  до разведения на CDN, резервирование не спасает.
- Использование трёх потоков повышает входящий трафик VPS и загрузку
  памяти/CPU. Следите за панелью нагрузки.
- Реальная стабильность, совместимость с LG/Samsung и соблюдение
  ограничений провайдера должны подтверждаться тестированием.

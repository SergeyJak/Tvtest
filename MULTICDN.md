# HeySmart TV: резервирование CDN для всех каналов

## Принцип

Все каналы в трёх M3U кабинетах поддерживают Multi-CDN при просмотре:
- **Основной** использует собственную подписку в первую очередь.
- **Вадим** использует собственную подписку в первую очередь.
- **Кристина** использует собственную подписку в первую очередь.

Если выбранный канал перестаёт продвигать плейлист телевизора
(или исходный CDN перестал отдавать сегменты), шлюз пробует **тот же канал**
через одну из остальных подписок. Смена ради небольшого ускорения загрузки
не производится. При стабильном восстановлении домашнего CDN (минимум
18 секунд реального продвижения его HLS) шлюз возвращает просмотр домой.

**Подмена не меняет M3U / EPG / токен / идентификатор канала для ТВ.**
Мультиплексор поддерживает отдельную монотонную HLS-шкалу для каждого
просматриваемого канала в каждом кабинете и ставит
`EXT-X-DISCONTINUITY` при смене исходного потока. Небольшие скачки
по времени эфира при переключениях возможны.

### Быстрое переключение каналов

Если несколько телевизоров используют один кабинет, добавьте к M3U-ссылке
каждого телевизора свой постоянный параметр, например
`/TOKEN/channels.m3u?device=living-room` и
`/TOKEN/channels.m3u?device=kitchen`. Обновите плейлист на каждом ТВ.
Параметр переносится в ссылки каналов. Быстрая отмена незавершённого
запуска доступна запросам с таким идентификатором.

После выбора канала шлюз перенаправляет запрос на HLS-ссылку текущего сеанса.
Плейлист завершённого сеанса отвечает 409. В кабинетах с одним слотом
повторные запросы к исходной ссылке канала блокируются на 10 секунд после
переключения. В этот интервал быстрый ручной возврат по той же ссылке
тоже получит 409. Прежние M3U-ссылки продолжают работать.

## Проверка соответствия каналов

Шлюз ищет точное название в обоих каталогах, игнорируя регистр и лишние
пробелы. Если обе подписки указывают группу, она тоже должна совпасть.
Для одноимённых каналов, например региональных выпусков новостей,
сочетание названия и группы должно быть уникальным в каждом каталоге.
Шлюз читает группу из `#EXTGRP` или атрибута `group-title`. Порядок строк
используется только для сохранения ранее выданных идентификаторов ТВ и EPG.

Если резервного канала нет, есть несколько неоднозначных дубликатов,
или другой кабинет занят своим зрителем, резерв не запускается.
Шлюз не заменяет канал похожим SD/HD, каналом с похожим названием,
или случайной трансляцией. **Все каналы поддерживаются**, но
автоматический резерв возможен лишь там, где поток этого же канала
существует в другом кабинете.

## Ограничение нагрузки

- Резервные потоки запускаются только **по запросу просмотра**, а не
  на весь каталог из нескольких тысяч каналов.
- Каждая подписка может быть текущим источником для **своего телевизора
  и максимум одного гостевого**, так что три зрителя не оказываются
  на одном CDN.
- Фоновые источники не должны вытеснять активного хозяина кабинета.
  Когда телевизор меняет канал, шлюз освобождает его гостевое место и
  останавливает резервы, которые больше никому не нужны.
  Если свободного резервного потока нет, воспроизводится доступный буфер;
  отсутствие зависаний в этом случае гарантировать нельзя.
- Брошенные виртуальные HLS-кеши убираются автоматически примерно через
  70 секунд без запросов манифеста. Ссылки на сегменты привязаны к
  конкретному кешу. После его удаления шлюз отвечает HTTP 404 даже при
  повторном открытии канала. Токены и адреса источников не
  возвращаются браузеру или в публичный статус другого кабинета.
- Один и тот же Edem может иметь сбой **до** разделения на региональные
  CDN. В таком случае все три подписки могут оказаться неисправны.

## Админка

На `https://tv.heysmart.lv/admin/` открой **CDN-монитор**.
Сначала выбери телевизор (Основной / Вадим / Кристина), затем канал из
списка просмотренных. Видны активный источник, возраст последних кадров,
запас видеобуфера, готовность резервов, число зрителей на источнике
и история переключений. Подробности о фоновых потоках доступны после входа
в админку. Данные обновляются примерно каждые 15 секунд.

Обзор показывает отдельную карточку каждого активного телевизора. При
совместном просмотре у одного источника видны имена всех кабинетов,
получающих от него видео. Гостевое место учитывается отдельно от места
владельца. При потере связи с админкой текущие показатели скрываются.

Для каждого канала сохраняются последние 20 событий. После освобождения
видеокеша шлюз держит историю 32 последних каналов на кабинет до своего
перезапуска.

## Обновление VPS

После слияния PR, когда **никто не смотрит ТВ**:

```bash
cd ~/Tvtest && git pull --ff-only
sudo systemctl restart iptv-gateway.service iptv-admin.service
sudo systemctl is-active iptv-gateway.service iptv-admin.service
```

**Важно:** перезапуск `iptv-gateway.service` прерывает текущие
трансляции; телевизору может потребоваться заново выбрать канал.
M3U и регионы CDN менять не требуется, если три кабинета уже настроены.

Если регионы менялись в самом Edem, сначала обнови сохранённые
M3U URLs через `python3 iptv_profile_jobs.py --refresh-m3u --m3u-only`.
Последний успешный EPG остаётся до завершения следующей генерации.

### Откат только Multi-CDN, без отката PR

```bash
cd ~/Tvtest
touch .iptv_profiles/multicdn.disabled
sudo systemctl restart iptv-gateway.service
```

Для повторного включения:
```bash
rm -f .iptv_profiles/multicdn.disabled
sudo systemctl restart iptv-gateway.service
```

Эксперимент требует реальной проверки на устройствах Samsung/LG.
